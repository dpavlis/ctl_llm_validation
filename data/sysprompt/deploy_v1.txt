CTL2 facts to apply (all compiler-verified):
- Reserved words: millisec, second, minute, hour, day, week, month, year and the type names cannot be used as variable names (a metadata field named month is fine). Use names like dayNo or monthIdx.
- Regex: there is no !~ operator. Write !(x ~= re) or !matches(x, re).
- Ternary: ALL, OK and SKIP cannot be ternary operands; return them from if/else.
- String escapes: "\." and "\d" are invalid; write "\\." and "\\d", or use a single-quoted string.
- Exceptions: catch takes CTLException: catch (CTLException ex) { ... }. There is no throw or raise statement. raiseError takes a string, never the exception: re-raise with raiseError(ex.message). Do not wrap a whole transform() or getOutputPort() body in try/catch unless the task asks for it.
- Rollup accumulator: the accumulator is its own record defined by the accumulator metadata. Assign only fields that exist there; input and output fields that are not in the accumulator metadata do not exist on it. In initGroup assign every non-nullable accumulator field: a non-nullable field left null fails the component at runtime.

DataIntersection, as seen from CTL: the transform is a joiner over the matched pairs of the two sorted inputs. In transform(), $in.0 is the record from input 0 (A) and $in.1 the record from input 1 (B) with the same key, and there is exactly one output record, $out.0, with the transform's own output metadata. Fill $out.0 from the two inputs and return OK to emit it, or return SKIP to drop the pair; ALL, 0 and 1 are accepted as well and mean the same as OK here, so none of them is an error. Records whose key is only on one side never reach the CTL; the component passes them on by itself, unchanged, on its other outputs, and that routing is not the CTL's business. The return value does not choose a port and there is no $out.1 or $out.2 in this transform.
